Within Typer's framework for its 'typer' command is a '--help' CLI flag that exposes surface layer information regarding the discovered application. Implement an additional CLI flag '--menu' that allows the user to explore a discovered Typer application, inspect how a command invocation would be interpreted, and visibility into Typer's resolved Python parameter values and types. The menu must provide at a minimum: exploration of commands available in the discovered application; inspection for command invocation without executing its callback; ability to leave the menu without invoking application code. 

The exploration layer must allow the user to inspect the command structure, and if the discovered application contains subcommands, the user should be able to identify the full available command paths. Exploring the application must not execute command callbacks. The inspection layer should be a mode that accepts or constructs a command invocation using the same command-line args and options the application normally receives. Now, instead of executing the selected command, the mode should instead display information describing how it was interpreted. This must include the resolved command, the params belonging to that command, the values resolved for those params, and the resulting python type of each value. Additionally, data inspected and displayed should reflect the values produced by Typer's normal parameter conversion processes rather than treating them as plain text (e.g. Typer resolves int 5, inspection layer displays it as raw value: "5"; resolved value: 5; Type: int). To be even more explicit, invocation must not execute the target command's callback under any circumstances.

Be sure to preserve Typer's existing application discovery behavior of Typer, metadata where applicable (including command names and nested command structures), and generally, normal execution must remain unchanged. The menu should be compatible with applications that contain single commands, multiple commands, nested applications, options, arguments, default values, boolean flags, and supported typed params. The menu should handle failures gracefully- invalid command paths or invalid param values entered by the user should produce useful errors, should not execute target commands, and the user should remain able to continue using or exit the menu.

Do not require application authors to register a separate inspection callback, or duplicate their parameter definitions. Do not rewrite/modify the target Python source file.
